# aiv-airflow-bench

Public corpus and product bench for **[AIV Integrity Gate](https://github.com/vaquarkhan/aiv-integrity-gate)**.

**Live report:** https://vaquarkhan.github.io/aiv-airflow-bench/

This repository is not apache/airflow. Apache Airflow® is a trademark of the ASF.

The window for every count below is **22 Oct 2025 through 22 Oct 2026**. Counts were taken on 22 Oct 2026 with `gh` against the GitHub search API and, for Apache lists, the Pony Mail API at `lists.apache.org`. A search `total_count` is the number GitHub returned for that query. It is a sample frame, not a census of AI-authored changes.

## How a benchmark case is scored

AIV scores a **git diff**, not the issue text. One case is a public pull request plus a label.

1. The case records `repo`, pull-request number, head SHA, and the patch (stored under `corpus/`).
2. [`run-e2e-benchmark.py`](https://github.com/vaquarkhan/aiv-integrity-gate/blob/main/benchmarks/airflow/scripts/run-e2e-benchmark.py) in the gate repo checks that PR out into a temporary git workspace.
3. It runs `java -jar aiv-cli --workspace <dir> --diff <base> --head HEAD --output-json <report>`.
4. Exit code 1, or any gate with `blocks_ci` still failing, is a **hard fail**.

`label.expect_hard_fail` is true only when the patch itself contains an objective marker. The same regexes are used while collecting and while scoring:

| Marker | What it matches |
|---|---|
| `merge_conflict` | A conflict marker at the start of a line |
| `ai_search_replace` | `<<<<<<< SEARCH` or `>>>>>>> REPLACE` |
| `ai_elision` | “rest of the code unchanged”, `YOUR_CODE_HERE`, `INSERT_YOUR_CODE` |
| `ai_assistant_chatter` | “as an AI language model”, “here’s the updated code” |
| `ai_attribution` | `generated by ChatGPT/Claude/Copilot/Gemini/AI` inside the patch |

Verdicts from the runner:

| Situation | Verdict |
|---|---|
| Hard fail expected, and the gate hard-fails | true positive |
| Hard fail expected, and the gate passes | false negative |
| Hard fail not expected, and the gate hard-fails on a control or closed-unmerged sample | false positive |
| Hard fail not expected, and the gate passes | true negative |

Labels used on the real-history sample:

| Label | Meaning | `expect_hard_fail` |
|---|---|---|
| `objective_slop` | A marker above is in the patch | true |
| `ai_disclosed` | Filled `Generated-by:` trailer, or a checked AI checkbox. The Airflow placeholder `Generated-by: [Tool Name]` does not count | false |
| `ai_slop_discussion` | Slop, vibe-coding, or hallucination language outside the project’s PR template | false |
| `ai_tool_mention` | Names a model or tool | false |
| `merged_control` | Merged, no filled disclosure, no slop language, no marker | false |
| `closed_unmerged_sample` | Closed without merge. Population only | false |

Disclosure is recorded so a reviewer can see it. It is not a fail label. Closed-without-merge is not a slop label. Template sentences such as “Low-effort AI-generated PRs will be closed”, curl’s “do not paste massive AI generated explanations”, and COSMIC’s “I have not included any LLM generated content” checklist are stripped before labeling.

These real diffs are collected and labeled. They have not been scored with `aiv-cli` in this workspace, because no JAR was present. The scored product numbers further down come from the labeled fixtures and the abandoned-PR recreation, which already ran through the gate.

Oversized diffs were skipped: Airflow proof rows over 4,000 additions or 50 files; the other benches over 5,000 additions or 40 files. Each slice keeps the latest search page, not every hit.

## Where the rows came from

Collectors (re-runnable, rate-limited at about 30 GitHub searches per minute):

| Script | What it wrote |
|---|---|
| `corpus/collect_ai_year.py` | Every Airflow issue in the window, end-to-end files for lexically flagged issues, and the dev-list mbox index |
| `corpus/collect_e2e_proof.py`, `corpus/fill_claude_gaps.py` | Bench 1, the stratified Airflow pull-request sample |
| `corpus/collect_slop_benches.py`, `corpus/repair_slop_benches.py` | Benches 2–4. The repair pass dropped template-only “AI generated” hits |
| `corpus/collect_hit_benches.py` | Benches 5–7, after a maintainer had publicly described an AI pull-request problem |
| `corpus/check_inbox_threads.py` | Lookup of the Sep–Oct 2026 `dev@airflow.apache.org` inbox screenshots |

Apache mail used `https://lists.apache.org/api/stream.json` (`list=dev`, project domain). A thread URL is `https://lists.apache.org/thread/{tid}`.

## Reproduce

Scored fixtures (gate repo):

```powershell
git clone https://github.com/vaquarkhan/aiv-integrity-gate
cd aiv-integrity-gate
mvn -pl aiv-cli -am package -DskipTests
python benchmarks/airflow/scripts/run-labeled-benchmark.py
python benchmarks/airflow/scripts/benchmark-abandoned-labeled.py --limit 60
```

Rebuild this corpus (bench repo, `gh` authenticated). Each script is resumable only where it already skips stored PR files. A zero from GitHub search is split by date before it is trusted. Do not treat a single empty page as an empty month.

```powershell
python corpus/collect_ai_year.py
python corpus/collect_e2e_proof.py
python corpus/fill_claude_gaps.py
python corpus/collect_slop_benches.py
python corpus/repair_slop_benches.py
python corpus/collect_hit_benches.py
```

To score a real-history case once `aiv-cli.jar` exists, point `run-e2e-benchmark.py` at a cases file whose rows have `repo`, `pr`, and `label.expect_hard_fail`. Bench 1 rows are in `corpus/e2e-proof/cases.json`. Benches 2–7 are in `corpus/benchmarks/<project>/cases.json`.
